## 2. CASE DOMAIN

Model: ONE case domain — support_cases with its messages, internal notes, timeline, links, assignment and escalation history (nine tables) — and three scoped surfaces over it: customer, restaurant, service desk. One service writes a case (SupportCaseService); one place moves a status (SupportCaseStateMachine).
Public ID: a uuid in every answer; the numeric key never leaves the database.
Case Number: CS- and eight characters of an alphabet without 0, 1, I and O (for example CS-7G2F2487); unique (index + retry); generated by the server; it is NOT an authorization — another requester gets 404 by number as by id.
Requester Types: CUSTOMER, RESTAURANT, ADMIN, SYSTEM — derived from the token or the code path; a requester type in a request is refused.
Sources: CUSTOMER_WEB, ANDROID, RESTAURANT_DASHBOARD, ADMIN, and the system's SYSTEM_ALERT, PAYMENT_RECOVERY, REFUND_RECOVERY, FINANCE_RECONCILIATION (reconciliation differences and provider disputes), SECURITY.
Categories: 14 with subcategories, as configuration (backend/config/support.php): ORDER, PAYMENT, REFUND, PICKUP, RESTAURANT, ACCOUNT, PROMOTION, REVIEW, SETTLEMENT, PAYOUT, DISPUTE, TECHNICAL, SECURITY, OTHER — each with its audiences, first queue, first priority and restricted class. Defaults, PENDING BUSINESS APPROVAL (CF-510).
Priorities: LOW, NORMAL, HIGH, URGENT — from the category; changed only on the desk, with a reason and an audit record.
Statuses: OPEN, ASSIGNED, IN_PROGRESS, WAITING_FOR_CUSTOMER / RESTAURANT / PROVIDER / FINANCE / INTERNAL, RESOLVED, CLOSED, REOPENED, CANCELLED. A step that is not allowed answers 409. Requesters read OPEN, IN_PROGRESS, WAITING_FOR_YOU, RESOLVED, CLOSED, CANCELLED.
Resolution Codes: a code and a note on every resolution and cancellation. REFUND_COMPLETED is accepted only when a linked refund is REFUNDED in the refund domain (e2e C2 → 409, C4 → accepted).
Versioning: a version on the case; every desk change sends the version it read (409 case_version_conflict) — also a reply that makes the case wait and the desk's own summary. Plain messages and notes do not move it. Two administrators through two API processes: one wins (e2e F2).

## 3. CUSTOMER SUPPORT

Create Case: POST /customer/support/cases (optional Idempotency-Key; at most 20 cases being worked on). Customer Web: Help › Contact support, and "Get help" on an order and on a refund. e2e A1, U2.
Case List: own cases, open / closed, unread mark. e2e U1, U4.
Case Detail: number, status in the customer's words, the linked records as their domains have them, what the customer may do. No priority, queue, assignee, target or note. e2e A1, U2.
Reply: with a client_message_id — a retry writes nothing twice (e2e B3, U4). A resolved or closed case takes no reply.
Order Link: by order number; the customer's own only (another customer's order: 404, no case written — e2e A2). A record the desk attaches is shown to the customer only when it is their own (SupportHardeningTest).
Payment Link: by payment id or PAY- reference; read as VERIFIED / FAILED / CANCELLED / EXPIRED / PROCESSING — never the payment domain's review words (BUG-281).
Refund Link: by refund id or RFD- reference, in the refund words of Module 35 (e2e C1: REQUIRED; C3: REFUNDED once the refund domain completed it).
Close: confirm a resolved case (CLOSED) or withdraw an open one (CANCELLED / USER_WITHDREW). The request must say which is meant and is decided under the lock of the case (BUG-279). e2e B5, H1, U6.
Reopen: inside the window (14 days after RESOLVED, 7 after CLOSED — configuration, CF-511), with a message. e2e H1, U6.
Notifications: three notices through the Module 33 domain — case opened (inbox), support replied, case resolved — each once, never for a note, never quoting the case; the target SUPPORT_CASE opens the case by its number (e2e A1, B2, B5).

## 8. CASE MESSAGES

Restaurant: shown with the restaurant's own staff names to the restaurant.
Support: shown as SUPPORT to requesters — no administrator name leaves the desk.
System: a system case has no conversation (nobody to reply to); what the system saw is an internal note marked SYSTEM (e2e D1, U7).

Idempotency: client_message_id / client_note_id unique per case; Idempotency-Key on opening a case (e2e B1, B3).

Refund: customers (own) and the desk. e2e C1.

Settlement: restaurants with the finance permission, and the desk (backend tests; e2e E5).
Payout: the same rule (backend tests).
Dispute: the system and the desk only (e2e D4, U7).
Review: the desk only (SupportLinkedRecordsTest).
Authorization: a requester names only their own records in typed fields (404 otherwise, nothing written); an administrator attaches only what they may read (403 with the missing permission); a panel shows the record's state only to a viewer who holds that domain's view permission — otherwise the reference and which permission is missing.

## 10. DOMAIN AUTHORITY
